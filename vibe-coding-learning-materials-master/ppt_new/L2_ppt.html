PART 02 / PROMPT ENGINEERING
PRD 结构化提示词示例
🧑‍💻 Role 你是资深产品经理，擅长AI教育产品需求分析，将复杂算法转化为师生易用的功能模块，熟悉教育场景下的用户痛点、数据闭环与业务增长逻辑，具备跨团队协作能力（后端、前端、AI工程师）。
🎯 Objective 开发一个AI驱动的数学教学应用生成平台。该平台需具备智能题目分析、交互式教学应用生成、用户系统、内容互动、语义相似度推荐、管理后台、实时任务追踪和性能优化等核心功能。
🌏 Context 目标用户为学生、数学教师、教育机构内容创作者。他们需要一个能够快速将任意数学题目转化为互动式教学工具的平台，用于课后练习、备课制作课件、在线教育内容生产等场景。
⛓️ Constraint 前端Tailwind + 新中式风格；后端FastAPI，MySQL + ChromaDB；DeepSeek分析题目结构，Gemini生成HTML；JWT认证；异步任务队列；生成代码内嵌Tailwind、响应式且无外部依赖。
👉 基于角色、目标、背景和约束，生成一份详细的产品需求文档（PRD）
PART 02 / Product Requirement
产品需求文档-章节概览
1. 项目概述：AI 驱动数学教学应用生成，核心是把数学题快速转成可教学、可复用的交互页面。
2. 用户角色：学生、教师、管理员三类角色分别对应练习、备课、管理三种使用场景。
3. 功能需求：智能题目分析、标题分类、交互 HTML 生成、收藏评论、语义推荐、管理后台。
4. 非功能需求：强调性能、稳定性、安全性，保证题目生成速度、页面可用性和数据安全。
5. 技术架构：前端使用原生 HTML/CSS/JS 与 Tailwind，后端使用 FastAPI、MySQL、ChromaDB。
6. 数据模型：User、Content、Comment、Like、Favorite、Captcha 等对象支撑账号、内容和互动能力。
7. API 接口设计：围绕题目分析、页面生成、用户互动、推荐检索等能力进行接口拆分。
8. UI/UX 设计要点：强调新中式风格、清晰层级、交互反馈和移动端适配。
9. 部署方案：结合 Nginx、Uvicorn、systemd 和云数据库，形成可上线部署流程。
10. 测试计划/风险评估：覆盖功能测试、性能测试、错误兜底和版权风险控制。

PART 03 / BACKEND · ITERATIVE
后端功能优化：先判断，再抽取，再生成
阶段 1：输入判定
先判断是否数学题，并识别是否存在独立图形，避免无效生成
↓
阶段 2：题干抽取
剥离题号、闲聊、无关信息，只保留可用于解题的核心题目文本
↓
阶段 3：教学输出
输出结构化教学步骤，再生成可交互的教学页面 HTML
PART 03 / BACKEND · STEP 1
输入判定优化：减少无效调用
问题
用户输入可能是闲聊、非数学内容，直接生成会浪费算力
+
关键优化提示词
“先判断是否为数学题；若不是，直接返回统一拒绝标记和友好提示，
不进入后续流程”
↓
优化后
服务先筛选再处理，显著降低无效任务和异常输出，节省调用成本
PART 03 / BACKEND · STEP 2
题干抽取优化：把脏输入变干净数据
问题
原始输入常混有题号、答案、闲聊，导致后续生成偏题或漏条件
+
关键优化提示词
“必须剥离题号和无关文本；仅保留完整题干、数学条件与符号；
统一输出结构化 JSON 字段”
↓
优化后
题目字段更稳定，后续教学脚本可直接复用，减少人工返工
PART 03 / BACKEND · STEP 3
生成链路优化：从结构化需求到教学页
问题
直接让模型生成页面，易出现步骤跳跃、讲解不连贯、无法课堂演示
+
关键优化提示词
“先输出默认参数、解题方法、分步演示逻辑；
再按步骤生成教学页面，保证左右联动与可回看”
↓
优化后
后端形成可维护流水线：判定 → 抽取 → 编排 → 生成 → 返回页面
PART 03 / FRONTEND · ITERATIVE 01
界面结构优化：先搭信息骨架
初版问题
信息区块混在一起，讲解时用户找不到重点
+
关键优化提示词
“将页面拆分为标题区、画布区、步骤区、控制区，
保持每块只承载一种信息”
↓
优化后
结构清晰，线上讲解时更容易跟着节奏走
PART 03 / FRONTEND · ITERATIVE 02
视觉优化：局部截图 + 修正指令
初版问题
按钮太方、颜色沉闷、层次感不足
+
关键优化提示词
“将按钮改为圆角20px，使用暖黄渐变，
增加纹理和轻阴影，强化主次层级”
↓
优化后
视觉更柔和，重点按钮更突出，用户操作更直觉

每次只改一个局部，迭代快、风险低、效果可验证。

PART 03 / FRONTEND · ITERATIVE 03
交互优化：加载反馈与结果提示
初版问题
点击后页面无反馈，用户不确定是否正在处理
+
关键优化提示词
“增加全屏 Loading 动画 + 底部 toast 成功提示，
并保持状态切换平滑”
↓
优化后
等待可感知，完成可确认，线上演示更稳定
PART 03 / FRONTEND · ITERATIVE 04
教学体验优化：让讲解可跟随、可回看
初版问题
讲解步骤与画面不同步，回看困难，听课节奏容易断。
+
关键优化提示词
“用 currentStep 统一控制画布、讲解气泡和右侧步骤高亮；
支持回看并自动展开当前讲解。”
↓
优化后
讲解节奏一致、回放清晰，适合线上分享与课堂复用。
步骤联动 轨迹可视化 全屏讲解 移动端适配
