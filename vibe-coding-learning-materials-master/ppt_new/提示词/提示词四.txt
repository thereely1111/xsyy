【界面结构优化】
# 角色
你是前端架构与 UI 专家，擅长 Tailwind CSS 和响应式布局，尤其关注教育产品的信息层级与视觉引导。

# 背景
当前 XSYY 平台的教学应用详情页（`frontend/src/pages/detail.html` 或生成的教学应用 HTML）存在**信息区块混杂**问题：题目描述、动态画布、解题步骤、交互练习控件堆叠在一起，用户（尤其是学生）在讲解或自学时难以快速定位重点，学习节奏混乱。

# 任务
基于产品需求文档（PRD）和技术架构文档，**重构教学应用详情页的 HTML/CSS 结构**，将页面**严格拆分为四个独立区块**，每个区块只承载一种信息类型，并使用视觉分隔（留白、边框、阴影）强化区域边界。

## 四个区块的定义

| 区块名称 | 承载内容 | 设计要点 |
|---------|----------|----------|
| **标题区** | 题目标题（≤10字）、难度标签（简单/中等/困难）、主标签/子标签 | 顶部固定或靠上，字体醒目，标签使用圆角小胶囊样式 |
| **画布区** | 动画演示、几何图形、函数图像、动态交互画布（如可拖拽的点、滑块控制参数） | 占据视觉中心，背景浅米白，有轻微内阴影，画布至少 400px 高，支持响应式 |
| **步骤区** | 分步讲解（步骤标题 + 详细解释 + 公式），可折叠或逐步骤高亮 | 使用卡片列表，每一步之间用虚线分隔，当前步骤有左侧边框强调色 |
| **控制区** | 交互式练习控件（按钮、滑块、输入框、选择题）与实时反馈 | 位于步骤区下方或右侧（桌面端可用 flex 行布局），控件间距统一，反馈提示用柔和色彩 |

## 布局要求
- **桌面端（≥1024px）**：画布区与步骤区可左右并排（画布占 50%，步骤区占 50%），控制区跨列底部。标题区全宽顶部。
- **移动端（<768px）**：所有区块垂直堆叠，画布区高度自适应，步骤区字体略大。
- 使用 **Tailwind CSS** 实现，不引入额外 CSS 框架。
- 保持**新中式风格**：主色墨蓝 `#1a365d`，背景米白 `#f7f3e9`，强调色浅青 `#a3d9ff`，圆角 `rounded-xl`，阴影柔和。

## 交互增强
- 步骤区支持**点击某一步骤**，画布区动态展示对应步骤的图形变化（需要预留 JavaScript 事件接口，示例代码中用注释说明）。
- 控制区中任何交互（滑块变化、答案提交）应实时在画布区或步骤区给出视觉反馈，无需刷新页面。

## 现有文件修改范围
请修改以下文件（或提供全新版本）：
- `frontend/src/pages/detail.html` —— 用于展示已生成的教学应用详情（包含上述四个区块，并通过 iframe 或直接嵌入 HTML？实际上生成的教学应用自身也应遵守此结构。因此需要**同时修改生成教学应用的模板**）
- `app/services/ai_service.py` 中的 `generate_application` 方法所使用的 **HTML 模板**（Gemini 生成的 HTML 应遵循同样的四区块结构）。请给出新的 Prompt 片段或示例模板，确保 Gemini 输出符合该结构。

## 输出要求
1. 提供 **重构后的 `detail.html`** 完整代码（含 CSS 和基础 JavaScript 框架，但动态数据从后端 API 获取）。
2. 提供 **新中式四区块布局的静态示例 HTML**（不依赖后端，纯演示结构），可直接在浏览器中查看分区效果。
3. 提供 **修改 `ai_service.py` 中生成 HTML 的 Prompt 建议**（如何描述四区块要求，让 Gemini 遵守）。
4. 用文字说明每个区块的响应式断点与边距规范（例如：区块间距 `mb-8`，内边距 `p-6`）。

## 验收标准
- 视觉上四个区块边界清晰，用户在 3 秒内能理解每个区域的作用。
- 移动端无水平滚动条，所有文字可读。
- 步骤区可折叠/展开（默认全部展开），降低信息密度。
- 控制区至少包含一个交互示例（如调节 a、b、c 系数的二次函数滑块），并实时更新画布区图像。

【视觉优化】
# 角色
你是 UI 视觉专家，擅长 Tailwind CSS 定制与微交互动效，尤其关注教育产品的操作直觉与视觉舒适度。

# 背景
当前 XSYY 平台的前端存在**视觉体验问题**：
- 按钮过于方正（border-radius 不足 8px），缺乏亲和力
- 色彩偏沉闷（大面积墨蓝/灰色，缺少提亮元素）
- 主次按钮层级不明显（所有按钮样式接近）
- 缺少微纹理和轻阴影，界面显得“扁平且单薄”

# 任务
基于现有 **新中式风格**（墨蓝主色 #1a365d，米白背景 #f7f3e9，强调色浅青 #a3d9ff），对全局按钮及关键交互元素进行**视觉升级**。具体要求如下：

## 1. 按钮圆角统一为 20px
- 所有 `<button>`、`.btn` 类元素：`rounded-[20px]`
- 辅助小按钮（如编辑、删除）可略小：`rounded-2xl`（16px）

## 2. 主按钮样式（Primary）
- 背景：暖黄渐变 `linear-gradient(135deg, #f5b042 0%, #f28e2b 100%)`
- 文字：深灰色 `#2d2a24`（保证对比度）
- 阴影：`shadow-md`，hover 时 `shadow-lg` 并上浮 1px（`transform: translateY(-1px)`）
- 增加微纹理：使用 `::before` 伪类叠加微弱噪点（`background-image: radial-gradient(circle at 25% 40%, rgba(255,255,240,0.1) 2%, transparent 2.5%); background-size: 8px 8px;`）
- 边框：无边框，或细边框 `rgba(0,0,0,0.05)`

## 3. 次按钮样式（Secondary）
- 背景：透明 + 边框 1.5px 暖黄渐变
- 文字：墨蓝 `#1a365d`
- 圆角 20px 同主按钮
- hover 时背景变为极浅黄 `rgba(245,176,66,0.1)`

## 4. 危险按钮（如删除）
- 背景：透明 + 边框 1.5px 浅红 `#f8a7a7`
- 文字：暖红 `#c23d3d`
- hover 背景 `rgba(194,61,61,0.1)`

## 5. 层级强化
- 页面主操作（如“生成教学应用”、“上传题目”、“保存”）**必须使用主按钮样式**。
- 次要操作（如“取消”、“返回”、“重置”）使用次按钮样式。
- 卡片内的“点赞”、“收藏”使用纯图标按钮（hover 显示暖黄圆背景）。

## 6. 全局微质感
- 卡片背景：纯白 `#ffffff` 代替米白，增加 `shadow-sm` 和 `backdrop-blur-sm`（仅透明天色卡片）
- 输入框（input, textarea）：圆角 20px，边框 `#e2e0da`，聚焦时边框改为暖黄渐变（使用 `outline` + `border-image` 或纯色浅橙）
- 分割线：使用渐变 `linear-gradient(90deg, transparent, #e5e0d5, transparent)` 增加韵律

## 7. 动效辅助
- 按钮点击：`scale(0.97)` 快速回弹（`transition-transform` 0.1s）
- 加载状态：主按钮内显示旋转 loader，文字透明，防止重复提交

## 修改范围
- 全局样式文件：`frontend/styles/tailwind.css`（需添加自定义组件类和 utilities）
- 所有页面中的按钮类名统一替换（`index.html`, `upload.html`, `application.html`, `detail.html`, `profile.html`, `admin.html`）
- 提供一份 **CSS 补丁文件**（可内嵌或外链），包含上述纹理、渐变、阴影的完整定义。

## 输出要求
1. 提供 `tailwind.css` 中新增的 **自定义组件层**（`@layer components`）代码，定义 `.btn-primary`, `.btn-secondary`, `.btn-danger` 等类。
2. 提供 **全局样式补丁**（用于纹理和额外动效，因 Tailwind 默认不包含）。
3. 以 `detail.html` 为例，展示修改前后按钮样式的对比代码片段（关键按钮）。
4. 简要说明如何确保暖黄渐变与现有新中式色彩体系协调（色彩心理学：暖黄带来温和、激发兴趣）。

## 验收标准
- 主按钮一眼可辨识，视觉权重最高。
- 按钮圆角明显柔和，手指/鼠标悬停有明确反馈。
- 页面整体不再沉闷，纹理细节提升质感但不干扰内容阅读。

【交互优化】
# 角色
你是前端交互体验专家，擅长设计清晰的加载状态与用户反馈系统，尤其关注教育产品中的操作确定性与等待感知。

# 背景
当前 XSYY 平台的前端（各页面中的按钮点击事件，如上传题目、生成应用、点赞收藏等）存在**严重反馈缺失**问题：
- 用户点击按钮后，页面没有任何视觉反馈（无 loading、无禁用状态）
- 用户不确定操作是否被触发，容易重复点击
- 操作完成后无明确提示（成功或失败），用户需手动刷新或猜测结果
- 页面切换或数据提交时闪屏感强，不连贯

# 任务
基于现有技术栈（原生 HTML/CSS/JS + Tailwind CSS，无前端框架），为整个平台**统一增加全局操作反馈系统**，包括：

1. **全屏 Loading 动画**（适用于耗时操作如上传题目、生成应用）
2. **底部 Toast 提示**（适用于轻量操作如点赞、收藏、复制链接，以及成功/错误反馈）
3. **状态切换平滑**（按钮禁用、进度过渡、页面无闪动）

## 具体要求

### 1. 全屏 Loading 动画
- 触发场景：调用 POST `/api/problems`（上传题目）、POST `/api/applications`（生成应用）等预计耗时 >500ms 的操作。
- 样式：半透明黑色蒙层（`bg-black/50`），中央一个旋转的墨蓝色圆环 + 米白背景，并显示提示文字（如“AI 正在分析题目...”）。
- 使用 `z-50` 覆盖全屏，阻止背景点击（`pointer-events: auto`）。
- 提供全局函数 `showFullscreenLoading(text)` 和 `hideFullscreenLoading()`。
- 动画：圆环旋转 + 淡入淡出（`transition-opacity duration-200`）。

### 2. 底部 Toast 提示
- 触发场景：任何异步操作成功或失败时（包括点赞、收藏、评论、生成完成、复制链接等）。
- 位置：固定在浏览器底部中央（`fixed bottom-6 left-1/2 -translate-x-1/2`），圆角 32px，暖黄渐变背景，深色文字，带柔和阴影。
- 自动消失：成功提示 2.5 秒，错误提示 3.5 秒。
- 类型区分：
  - 成功：绿色系或暖黄渐变，勾号图标
  - 错误：红色系，感叹号图标
  - 普通信息：浅青或中性灰
- 提供全局函数 `showToast(message, type = 'success')`。
- 多个 Toast 应排队显示或同时显示（最多同时 3 个，堆叠向上）。

### 3. 按钮状态管理
- 点击后立即禁用按钮（`disabled` 属性），加上 `opacity-50` 和 `cursor-not-allowed`，防止重复提交。
- 如果操作需要全屏 loading，禁用按钮并显示 loading 文字（如“处理中...”）。
- 操作完成（无论成功/失败）后恢复按钮状态。
- 对于表单提交，在提交期间所有表单输入框应设为只读（`readonly`）。

### 4. 平滑状态切换
- 不要使用 `window.location.reload()` 刷新整个页面；数据变化应通过重新请求 API 并局部更新 DOM。
- 点赞/收藏等操作应乐观更新（先改变 UI 状态，若请求失败则回滚）。
- 生成应用时，轮询状态接口应平滑更新进度条，避免突变。

## 实现范围与文件修改
- **新建** `frontend/src/utils/feedback.js`：统一导出 `showFullscreenLoading`, `hideFullscreenLoading`, `showToast` 函数。
- **修改** `frontend/src/utils/api.js`：在 `apiRequest` 函数中统一拦截请求和响应，自动显示全屏 loading（可选配置）和 toast 错误提示。为每个 API 调用添加 `showLoading` 和 `showSuccessToast` 选项。
- **修改每个页面**中的按钮点击事件处理器（`upload.html`, `application.html`, `detail.html`, `profile.html`），使用上述函数包裹异步操作。
- **修改** `frontend/src/utils/ui.js`：增加进度条更新时的平滑过渡（CSS transition）。

## 代码示例参考
### feedback.js 核心结构
```javascript
let loadingLayer = null;
export function showFullscreenLoading(text = '加载中...') {
  if (loadingLayer) return;
  loadingLayer = document.createElement('div');
  loadingLayer.className = 'fixed inset-0 bg-black/50 z-50 flex items-center justify-center transition-opacity duration-200';
  loadingLayer.innerHTML = `
    <div class="bg-white rounded-3xl p-6 shadow-xl flex flex-col items-center space-y-3">
      <div class="w-10 h-10 border-4 border-[#a3d9ff] border-t-[#1a365d] rounded-full animate-spin"></div>
      <p class="text-[#1a365d] font-medium">${text}</p>
    </div>
  `;
  document.body.appendChild(loadingLayer);
  loadingLayer.style.opacity = '1';
}

【教学体验优化】
# 角色
你是前端交互与教学体验专家，擅长设计步骤驱动的多模态教学内容同步机制，尤其关注在线讲解场景中的节奏控制与回看便利性。

# 背景
当前 XSYY 平台生成的教学应用 HTML（或详情页中的步骤区+画布区）存在**教学节奏混乱**问题：
- 步骤区与画布区的动画/图形变化缺乏同步（用户点击步骤或自动讲解时，画布不会联动）
- 缺少“当前讲解步骤”的视觉高亮和气泡引导
- 无法回看之前步骤并自动重放对应的画布状态
- 听课过程中如果走神，难以快速定位到正在讲的部分

# 任务
对教学应用详情页（或生成的教学应用 HTML 内部）进行**教学体验升级**，实现：

1. **统一状态变量 `currentStep`**（从 0 或 1 开始）
2. **画布联动**：改变 `currentStep` 时，画布区域动态更新为对应步骤的图形/动画/标注。
3. **讲解气泡**：画布内或旁边显示一个浮动气泡，展示当前步骤的简短提示（可配置）。
4. **右侧步骤高亮**：步骤列表中当前步骤有左侧边框、背景色或动画脉冲，自动滚动到视口内。
5. **回看功能**：点击任意历史步骤，将 `currentStep` 切换为该步骤，画布、气泡、高亮同步更新，且自动展开该步骤的详细解释（如果步骤可折叠）。
6. **自动讲解模式（可选）**：提供“自动播放”按钮，按顺序每 N 秒切换到下一步，支持暂停。

## 具体要求

假设教学应用由以下 JSON 驱动（可从后端 API 获取或嵌入 HTML 的 `<script>` 中）：
