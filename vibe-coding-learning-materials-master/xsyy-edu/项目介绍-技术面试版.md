# XSYY（象数演易）项目介绍（技术面试版）

## 1. 项目目标与定位

XSYY 是一个面向数学教育场景的全栈 AI 平台，目标是把题目输入自动转化为可交互教学 HTML，并围绕内容建立推荐、专题、分享、问答与后台治理能力。

核心不是“调用一次大模型”，而是“把 AI 能力产品化为稳定可运营系统”。

---

## 2. 架构设计

### 2.1 总体架构
- 前端：原生 HTML/CSS/JS 多页面应用（首页、详情页、个人中心、专题分享页、管理后台）。
- 后端：FastAPI 提供 REST API、任务处理、鉴权、数据访问与监控接口。
- 存储层：
  - MySQL：用户、教学内容、互动、专题、助教会话等结构化数据。
  - ChromaDB：题目向量嵌入与相似检索。
  - 本地存储：生成 HTML 与预览图文件。

### 2.2 AI 流水线
- 两阶段链路：
  1. 分析阶段（抽取题干、结构化要点、分类标签）。
  2. 生成阶段（输出单文件交互式教学 HTML）。
- 优势：分工明确，便于控制模型成本、提升可解释性与可维护性。

---

## 3. 核心模块拆解

### 3.1 任务与生成模块
- 异步任务模型：任务创建后进入后台处理，前端轮询状态。
- 状态机设计：pending/running/completed/failed，附带进度百分比。
- 结果产物：HTML、预览图、结构化 metadata。

### 3.2 用户与权限模块
- JWT 鉴权。
- 账号密码 + 手机验证码双登录链路。
- 个人资料、密码、手机号/邮箱绑定、找回密码。
- 用户级每日调用额度控制。
- 管理员基于用户名白名单隔离管理能力。

### 3.3 内容与互动模块
- 教学内容列表、检索、详情、下载、删除。
- 评论、点赞、收藏、浏览历史。
- 互动数据与内容数据关联，便于后续推荐与统计。

### 3.4 专题与分享模块
- 专题 CRUD。
- 内容加入/移出专题。
- 批量导入。
- 分享 token + 过期时间控制，对外公开访问。

### 3.5 相似推荐模块
- 对题目文本计算 embedding 并写入向量库。
- 相似检索接口按语义返回推荐内容。
- 删除/失败场景同步清理向量数据，避免脏数据。

### 3.6 AI 助教模块
- 会话摘要缓存（session 维度）。
- 问答记录落库。
- 相似问题匹配复用历史答案，减少重复调用。

### 3.7 监控与可观测性
- Prometheus 指标覆盖：HTTP、任务执行、连接池、缓存命中率。
- 健康检查与指标摘要接口支持运维侧接入。

## 4. 关键技术决策与取舍

### 决策 1：双模型分工而非单模型端到端
- 原因：将“理解题目”和“生成应用”拆开，降低提示词耦合。
- 收益：输出质量更稳定，定位问题更清晰。
- 代价：链路更长，需要更严谨的超时和异常处理。

### 决策 2：关系库 + 向量库分层
- 原因：结构化业务与相似检索需求差异明显。
- 收益：查询性能与模型演进互不牵制。
- 代价：要处理跨库一致性，尤其是删除与回滚流程。

### 决策 3：前端轮询而非实时推送
- 原因：实现复杂度低、兼容性好、部署成本可控。
- 收益：快速上线，维护简单。
- 代价：请求有冗余，需通过动态轮询节流优化。

### 决策 4：HTML 缓存与同题复用
- 原因：AI 生成成本高、耗时长。
- 收益：显著降低重复调用，提升响应速度。
- 风险：缓存失效策略和版本一致性需要额外治理。

## 5. 数据模型亮点

核心实体：
- User / VerificationCode
- Teaching / Comment / Like / Favorite / ViewHistory
- Topic（含 share token 与过期控制）
- AITeachingSession / AITeachingQA

设计特点：
- 互动模型独立建表，便于扩展统计维度。
- Topic 与 Teaching 关联支持内容资产分组与运营。
- AI 助教会话与问答分离，利于缓存和历史追溯。

## 6. 工程质量与稳定性

### 6.1 工程化能力
- 脚本化部署（dev/prod/rollback/migrate/version）。
- 数据迁移脚本体系。
- 配置环境隔离（.env + 默认配置）。

### 6.2 测试与诊断
- 提供接口与快速检查脚本。
- 提供数据库/环境检查与网关调试脚本。
- 支持测试模式，便于前后端联调。

### 6.3 安全基线
- JWT 身份验证。
- 密码哈希存储。
- 权限分层（普通用户/管理员）。
- 输入校验与数据库 ORM 防注入。

---

## 7. 可扩展性设计

- 业务扩展：可平移到多学科题型。
- 模型扩展：可替换分析模型与生成模型。
- 存储扩展：可将本地文件迁移到对象存储。
- 架构扩展：任务处理可外置到消息队列与独立 Worker。

---

## 8. 面试可重点讲的技术难点

1. 如何把大模型能力做成可维护的业务流水线，而不是“黑盒调用”。
2. 向量库与关系库双写的一致性策略与异常补偿。
3. 同题复用与问答复用如何在效果和准确率间平衡。
4. 任务异步化后，前端如何管理队列、进度与失败重试体验。
5. 管理后台如何支持运营配置变更且保持权限安全。

---

## 9. 总结

XSYY 的技术价值在于：以工程化方式把 AI 生成能力落地为稳定的教育平台，既能支撑高频内容生产，也具备后续平台化扩展的架构基础。
