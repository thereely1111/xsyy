# 部署检查清单

## 📋 使用说明

在每次部署前，按照这个清单逐项检查，确保部署顺利。

---

## 🔧 部署前检查（必须完成）

### 1. 代码检查

- [ ] 代码已提交到 Git
- [ ] 代码已推送到远程仓库
- [ ] 没有未提交的更改（`git status` 显示 clean）
- [ ] 代码已通过本地测试

**检查命令**：
```bash
git status
git log --oneline -5  # 查看最近5次提交
```

### 2. 分支检查

- [ ] 开发环境：在 `develop` 分支
- [ ] 生产环境：在 `main` 或 `master` 分支
- [ ] 分支已同步远程（`git pull` 无冲突）

**检查命令**：
```bash
git branch  # 查看当前分支
git pull origin develop  # 或 main
```

### 3. 环境变量检查

- [ ] `.env` 文件已配置
- [ ] 数据库连接信息正确
- [ ] API 密钥已配置
- [ ] JWT_SECRET 已设置（生产环境必须是强密码）

**检查命令**：
```bash
cd backend
cat .env | grep -v "PASSWORD\|SECRET\|KEY"  # 查看配置（不显示敏感信息）
```

### 4. 数据库检查

- [ ] 数据库连接正常
- [ ] 数据库迁移脚本已准备
- [ ] 已备份数据库（生产环境必须）

**检查命令**：
```bash
python backend/check_db.py
```

### 5. 依赖检查

- [ ] `requirements.txt` 已更新（如果有新依赖）
- [ ] 所有依赖包可以正常安装
- [ ] 已安装 Node.js（画法模板库装配/验收用；`node -v` 能输出版本号）

**检查命令**：
```bash
cd backend
source .venv/bin/activate
pip check  # 检查依赖冲突
node -v    # 画法模板路由需要（只用 Node 内置模块，不需要 npm install）
```

### 6. 服务器检查（生产环境）

- [ ] 服务器磁盘空间充足（至少 10GB 可用）
- [ ] 服务器内存充足
- [ ] 服务可以正常停止和启动

**检查命令**：
```bash
df -h  # 查看磁盘空间
free -h  # 查看内存
sudo systemctl status xsyy-backend  # 查看服务状态
```

## 🚀 部署时检查

### 开发环境部署

- [ ] 执行 `./deploy/deploy-dev.sh`
- [ ] 脚本执行无错误
- [ ] 服务启动成功
- [ ] 健康检查通过（访问 `http://服务器IP:8000/api/health`）

### 生产环境部署

- [ ] 已确认部署版本
- [ ] 已备份数据库
- [ ] 已备份代码
- [ ] 执行 `./deploy/deploy-prod.sh`
- [ ] 脚本执行无错误
- [ ] 服务启动成功
- [ ] 健康检查通过
- [ ] 功能测试通过（登录、创建任务等）

---

## ✅ 部署后检查

### 1. 服务状态

- [ ] 服务运行正常
- [ ] 日志无错误信息
- [ ] API 接口可以正常访问

**检查命令**：
```bash
sudo systemctl status xsyy-backend
curl http://localhost:8000/api/health
```

### 2. 功能测试

- [ ] 用户登录功能正常
- [ ] 创建任务功能正常
- [ ] 查看教学内容功能正常
- [ ] 其他核心功能正常

### 3. 性能检查

- [ ] 响应时间正常
- [ ] 无内存泄漏
- [ ] 数据库连接正常

**检查命令**：
```bash
# 查看资源使用
top -p $(pgrep -f "uvicorn app:app")

# 查看数据库连接
mysql -u user -p -e "SHOW PROCESSLIST;" database_name
```

## 🔄 回滚准备（如果部署失败）

### 回滚前检查

- [ ] 确认备份位置（`/opt/xsyy/backups/`）
- [ ] 确认回滚版本
- [ ] 已通知相关人员

### 回滚步骤

1. 停止服务
2. 恢复代码
3. 恢复数据库（如果需要）
4. 重启服务
5. 验证功能

**回滚命令**：
```bash
cd /opt/xsyy
./deploy/rollback.sh
```

## ⚠️ 紧急情况处理

### 如果部署失败

1. **立即回滚**
   ```bash
   ./deploy/rollback.sh
   ```

2. **查看日志**
   ```bash
   tail -100 /opt/xsyy/deploy.log
   sudo journalctl -u xsyy-backend -n 100
   ```

3. **通知相关人员**

4. **记录问题**
   - 错误信息
   - 发生时间
   - 影响范围

### 如果服务无法访问

1. **检查服务状态**
   ```bash
   sudo systemctl status xsyy-backend
   ```

2. **检查端口**
   ```bash
   netstat -tlnp | grep 8000
   ```

3. **检查防火墙**
   ```bash
   sudo firewall-cmd --list-all
   ```

4. **重启服务**
   ```bash
   sudo systemctl restart xsyy-backend
   ```

## 💡 小贴士

1. **每次部署前都要备份**
   - 脚本会自动备份，但建议手动备份数据库

2. **生产环境部署选择低峰期**
   - 避免影响用户使用

3. **保持部署记录**
   - 方便追踪问题和回滚

4. **定期检查备份**
   - 确保备份可用
