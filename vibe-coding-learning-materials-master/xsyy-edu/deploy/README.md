## 🗂️ 脚本文件说明

### 主要脚本

| 脚本文件 | 用途 | 使用场景 |
|---------|------|---------|
| `deploy.sh` | 主部署脚本 | 通用部署，支持 dev/prod |
| `deploy-dev.sh` | 开发环境快速部署 | 日常开发更新 |
| `deploy-prod.sh` | 生产环境部署 | 正式发布 |
| `rollback.sh` | 回滚脚本 | 部署失败时恢复 |
| `migrate.sh` | 数据库迁移 | 更新数据库结构 |
| `version.sh` | 版本管理 | 生成版本信息 |

### 使用方法

```bash
# 开发环境
./deploy/deploy-dev.sh

# 生产环境
./deploy/deploy-prod.sh

# 回滚
./deploy/rollback.sh
```

## 📖 常见场景

### 场景 1: 开发新功能

```
1. 创建功能分支
   git checkout -b feature/新功能

2. 开发并提交
   git add .
   git commit -m "添加新功能"
   git push origin feature/新功能

3. 合并到 develop
   (通过 GitHub Pull Request 或命令行)

4. 自动部署到开发环境

5. 测试通过后，合并到 main

6. 自动部署到生产环境
```

### 场景 2: 修复紧急bug

```
1. 从 main 创建 hotfix 分支
   git checkout -b hotfix/修复bug

2. 修复并提交
   git add .
   git commit -m "修复bug"
   git push origin hotfix/修复bug

3. 合并到 main（紧急）
   git checkout main
   git merge hotfix/修复bug
   git push origin main

4. 自动部署到生产环境
```

### 场景 3: 手动部署（自动部署失败时）

```
1. SSH 连接到服务器
   ssh user@server

2. 切换到项目目录
   cd /opt/xsyy

3. 执行部署脚本
   ./deploy/deploy-prod.sh

4. 检查部署结果
   sudo systemctl status xsyy-backend
```

## 💡 最佳实践

1. **永远不要直接修改 main 分支**
   - 必须通过 develop → main 的流程

2. **部署前一定要测试**
   - 先在开发环境测试
   - 确认没问题再部署到生产

3. **重要操作前要备份**
   - 数据库备份
   - 代码备份（脚本自动完成）

4. **遇到问题及时回滚**
   - 不要硬撑
   - 先回滚，再排查问题

5. **保持文档更新**
   - 记录每次部署的问题和解决方案
