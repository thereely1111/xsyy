> 配套文档：同目录 `README.md`（功能/API/冒烟说明）；本文档专讲**更新、部署后出问题怎么排查与解决**

## 一、必须理解的架构（本次事故根因所在）

智能体一体化后，**所有 `/tag-agent/*` 接口由 xsyy 后端 uvicorn:8000 提供**（`backend/app.py:1199-1204` 启动时注册路由，失败只 print 不阻断启动）。

公网访问链路是 **nginx 两重转发**：

```
浏览器 → Cloudflare → nginx 第一重（主 server，80/443，www.xsyy.top）
                          └── /api/*、/tag-agent/* → 后端 127.0.0.1:8000
                          └── 其余请求 → 第二重（xsyy-frontend.conf，前端/兜底层）
nginx 第二重（xsyy-frontend.conf）
    ├── location /api/        → proxy_pass http://127.0.0.1:8000
    ├── location /tag-agent/  → proxy_pass http://127.0.0.1:8000   ← 必须加！
    └── location /            → try_files ... /index.html  （SPA 兜底，返回 HTML）
```

⚠️ **核心教训：`/tag-agent/` 转发段必须同时存在于「两重」nginx 配置中，漏任一层，`/tag-agent/*` 请求就会被第二层的 SPA 兜底拦截，返回 HTML 页面。**

本次事故：第一重已加 `/tag-agent/` 转发，**第二重 `xsyy-frontend.conf` 漏加** → dashboard 的
`loadAgentHealth` 请求 `https://www.xsyy.top/tag-agent/health` 拿到的是 index.html → 前端报错。

## 二、症状速查（先判断是哪一层）

| 报错 / 现象 | 层级判断 | 处理方向 |
|---|---|---|
| `SyntaxError: Unexpected token '<', "<!DOCTYPE"... is not valid JSON` | **nginx 层**：接口返回了 HTML（SPA 兜底 / 50x 页） | 查 nginx 两重配置是否都加了转发段 |
| 接口返回 `{"detail":"Not Found"}`（JSON） | **后端层**：进程没这个路由 | 代码没更新 / 没重启 / 注册失败（见 §3.②） |
| 接口返回 `502 Bad Gateway`（HTML） | nginx 代理目标不通 | 后端没起 / 端口错 |
| 接口返回 JSON 但逻辑不对 | 后端业务问题 | 查后端日志 |

> 一句话口诀：**JSON 404 = 后端问题；HTML = nginx 问题。**

## 三、标准排查流程（由内到外，逐层排除）

在服务器（root shell）执行，按顺序：

### ① 后端是否存活（登录接口）
```bash
curl -sS -X POST 'http://127.0.0.1:8000/api/auth/login' -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"abcd1234"}' -w '\n[HTTP %{http_code}]\n'
```
预期 200 JSON。→ 排除"后端进程挂了"。

### ② 后端是否注册了智能体路由（看启动日志）
```bash
journalctl -u xsyy-backend --no-pager | grep -E "标签智能体路由|注册进程内" | tail -5
```
- 看到 `已成功注册进程内标签智能体路由` → 路由在 ✅
- 看到 `注册进程内标签智能体路由失败: xxx` → 按 xxx 处理（多为依赖缺失）
- **什么都没有** → 进程还是旧代码，`systemctl restart xsyy-backend` 后复查本行
  （注册代码在 `backend/app.py:1199-1204`，try/except 包裹，失败不阻断启动）

### ③ 后端直连路由（绕过 nginx）
```bash
curl -sS 'http://127.0.0.1:8000/tag-agent/health' -w '\n[HTTP %{http_code}]\n'
```
预期 200 JSON（未带管理员 token 时预期 401 JSON——**只要是 JSON 就说明路由已注册**）。
若 `{"detail":"Not Found"}` → 见 ②。

### ④ 公网链路对比（复现前端报错）
```bash
curl -sS 'https://www.xsyy.top/tag-agent/health' -w '\n[HTTP %{http_code}]\n' | head -c 400
```
- 返回 `<!DOCTYPE`/HTML → **nginx 层缺转发**（本次事故即此），进入 §四
- 返回 JSON → nginx 正常，问题在前端缓存，Ctrl+F5 强刷 / 无痕窗口验证

### ⑤ 浏览器端定位（确认失败请求是谁）
报错页面 F12 → Network → 找红色/失败请求，记录：**完整 URL + HTTP 状态码 + 响应前 200 字符**。
本次事故特征：同一页面 `/api/*` 全部正常，**仅 `/tag-agent/*` 返回 HTML** → 指向 nginx 缺转发。

## 四、修复步骤（nginx 两重转发都要有）

### 1️⃣ 定位两个配置文件里谁缺转发
```bash
grep -rn "www.xsyy.top" /etc/nginx/conf.d/ /etc/nginx/nginx.conf 2>/dev/null   # 找主配置
ls /etc/nginx/conf.d/                                                          # 找 xsyy-frontend.conf
grep -n "location /tag-agent/\|location /api/" /etc/nginx/conf.d/*.conf        # 谁有谁没有
```
判定：`/tag-agent/` 转发段 **必须同时出现在两重配置**；缺哪个补哪个。

### 2️⃣ 备份
```bash
cp /etc/nginx/conf.d/<缺失的文件> /etc/nginx/conf.d/<缺失的文件>.bak.$(date +%Y%m%d)
```

### 3️⃣ 插入转发段（每个缺的 server 块都加，`location /api/` 之后同级插入）
```nginx
    # 标签识别智能体 API：/tag-agent/* 必须转发到后端 8000，否则被 SPA 兜底返回 HTML
    location /tag-agent/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 30s;
        proxy_send_timeout 30s;
        proxy_read_timeout 30s;
    }
```
> 注意：一个文件可能有多个 server 块（80/443、不同域名），转发段要加在**实际服务对应域名的 server 块内**；插入到 server 块外会导致 `nginx -t` 语法报错。

### 4️⃣ 生效并复测
```bash
nginx -t && nginx -s reload
curl -sS 'https://www.xsyy.top/tag-agent/health' -w '\n[HTTP %{http_code}]\n' | head -c 400
```
预期 200 JSON → 强刷管理后台 dashboard 恢复。

## 五、智能体更新 / 部署后必查清单（Checklist）

每次更新部署智能体相关代码后，按此清单过一遍，可避免同类事故：

- [ ] **代码已更新到服务器**（git pull / rsync 目标路径正确）
- [ ] **后端已重启**：`systemctl restart xsyy-backend`
- [ ] **路由注册成功**：`journalctl -u xsyy-backend | grep 注册进程内标签智能体路由` 出现"已成功"
- [ ] **依赖齐全**：`.venv/bin/pip show agentscope pydantic-settings aiomysql`（一体化必需三件套）
- [ ] **本地直连通**：`curl http://127.0.0.1:8000/tag-agent/health` 返回 JSON（401/200 均可）
- [ ] **公网链路通**：`curl https://www.xsyy.top/tag-agent/health` 返回 JSON 而非 HTML
- [ ] **nginx 两重转发都在**：`grep -n "location /tag-agent/" /etc/nginx/conf.d/*.conf` 覆盖主配置 + xsyy-frontend.conf
- [ ] **新增接口同理**：本次若新增了非 `/api/` 前缀的接口，两重配置都要加转发段（**转发段与接口同批部署**）
- [ ] **仓库同步**：生产 nginx 改动回写仓库 `deploy/etc/nginx-公网/conf.d/`，防止配置漂移
