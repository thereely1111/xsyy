## 第一部分：运行环境说明（必读）

你的 scene_svg 将被注入到以下 Alpine.js 组件环境中：

### 已有的状态变量

- sceneStep：整数，从 1 开始递增（第 1 步 = 1，第 2 步 = 2 ...），代表当前教学步骤编号。**你的 SVG 中所有步骤相关判断必须使用 sceneStep**
- isBubbleExpanded：布尔值，气泡是否展开（由模板控制，你无需处理）

### 已有的模板组件（你不需要生成）

- 页面顶部标题栏（显示 title 和 summary）
- 右侧"完整解法"卷轴面板（自动渲染 steps 数组）
- 底部"回看 / 下一步"按钮
- 右侧固定"老师说"面板（自动读取当前步骤的 bubbleText 和 description，不浮层、不覆盖演示图）
- 全屏切换按钮
- KaTeX 数学渲染函数 renderMath()

### SVG 画布参数

- 视口：viewBox="0 0 820 620"
- 缩放模式：preserveAspectRatio="xMidYMid meet"
- 你的 scene_svg 会被放入 <g> 容器内，自适应缩放、保证完整显示（不裁剪），不要居中堆叠
- `bubblePos` 和 `arrowTarget` 都使用 820×620 SVG 画布坐标：字段保留但仅作语义占位
  （可填本步演示主体中心），模板不再绘制气泡或箭头；画布整幅可用，左上无禁区。

## 第二部分：scene_svg 技术规范

### 2.1 基本结构

- 只输出 SVG 内部片段：以 <g> 或 <defs> 开头，禁止包含 <svg>、<script>、<html>、<body>
- 可以使用：defs、style、g、rect、circle、ellipse、line、path、polyline、polygon、text、tspan、foreignObject、image（仅限 data: URI）、clipPath、mask、pattern、filter、linearGradient、radialGradient
- 所有元素必须在 820×620 视口内布局，铺满但不溢出

### 2.2 步骤可见性控制（核心机制：画布降噪与内容隔离）

生成 scene_svg 前，必须将所有元素划分为两个互斥层级：

- **核心持久层**：题目主体、后续仍需引用的基础图形、坐标轴、固定标签等，可以跨步骤保留，使用 `x-show="sceneStep >= N"`。
- **步骤临时层**：当前步骤的操作标记、计算过程、辅助线、轨迹、虚线箭头、局部高亮、讲解标注和阶段性结果，只服务于一个步骤，必须使用 `x-show="sceneStep === N"`，切换步骤后自动消失。

硬性规则：

- 变量名必须是 sceneStep（不是 currentStep）。
- 至少 8 个 x-show 条件块，其中至少 3 个为核心持久层的范围判断。
- **严禁使用 `sceneStep >= N` 控制任何步骤临时层元素；临时层只能使用 `sceneStep === N`。**
- 轨迹、高亮、辅助线、笔迹、虚线箭头和阶段性标注一律属于临时层，进入下一步必须消失，不得叠加。
- 持久元素只保留确实需要跨步骤存在的内容；同一视觉元素只生成一次，不得为凑步骤复制或残留临时元素。
- 建议使用 `<g id="persistent-layer">` 和 `<g id="temporary-layer-step-N">` 分组，但分组不能替代 x-show 条件。

### 2.3 过渡动画

使用 Alpine.js 的 x-transition 实现平滑切换，至少 3 处。组合 enter/leave/位移/透明度/缩放，使用大跨度 duration-700 到 1000。

### 2.4 运动轨迹

- 至少 2 条虚线轨迹，使用 stroke-dasharray 表现
- 轨迹受 sceneStep 控制显隐
- 给轨迹元素添加 class="dashed-line"

### 2.5 CSS 动画

在 scene_svg 内部用 <style> 定义至少 2 个 @keyframes 上下缓慢小幅度浮动的间隔三秒循环一次的动画，应用到关键视觉元素。

### 2.6 高级视觉效果

在 <defs> 中定义至少 2 个高级滤镜或渐变（如投影 drop-shadow、发光、质感渐变）。

### 2.7 数学公式渲染

**scene_svg 中（严格禁止 LaTeX）：**
- 后端校验会拒绝 scene_svg 中的 $...$、\frac、\sqrt 等 LaTeX 控制符
- 必须使用 Unicode 数学符号或预计算结果：×（乘）、÷（除）、π、√（根号）、²（平方）、³（立方）、≤、≥、≈、≠
- 分数用 HTML 排版或直接写出计算结果
- 示例：面积 = 长 × 宽 = 5 × 3 = 15（正确），面积 = $长 \times 宽$（错误，会被拒绝）

**steps 数组中（支持 LaTeX）：**
- description 和 bubbleText 字段支持 $公式$ 语法
- 模板的 renderMath() 函数会自动将 $...$ 渲染为 KaTeX 公式
- 示例："description": "平均数 = $\frac{总数}{份数} = \frac{16}{4} = 4$"

### 2.8 动态属性绑定

使用 Alpine.js 的 `:` 前缀绑定 SVG 属性（:x, :y, :fill, :transform 等），实现随步骤变化的动态效果。配合 CSS 过渡类（transition-all duration-700 ease-in-out）实现丝滑切换。

### 2.9 几何精准性（若题目涉及几何图形）

所有点坐标、线段端点、交点、垂足、对称点、圆心必须精确满足题意。垂直就必须数学上真正垂直，等长就真正等长。禁止凭视觉近似放置。

## 第三部分：视觉风格规范（新中式）

### 色彩体系

- 墨 #2b2b2b — 主要文字、重点线条
- 墨 #2b2b2b — 次要文字、常规线条
- 描边灰 #b9ad95 — 辅助元素、轨迹线
- 朱砂 #d6432f — 强调、高亮、关键数字
- 淡朱砂 #fee2e2 — 高亮背景底色
- 纸 #f4efe3 — 元素底色背景
- 禁止使用高饱和荧光色

### 构图要求

- 元素层次清晰，使用 filter/shadow 增加立体感
- 适当使用 Emoji 或微扁平化矢量图形增加趣味性
- 辅助线、标注等细节精致
- 禁止全画布背景层、无语义装饰元素、页面级 UI
- 视觉层级：关键数字/结论用大字号+朱砂红强调，辅助说明用小字号浅灰；避免满屏同级元素
- 每个步骤至少包含一个图形化表达（图标、数据条、圆环、坐标轴、几何示意等），禁止"纯文字卡片"堆叠

### 输出体量控制（重要）

- scene_svg 与 steps 合计尽量控制在 12000 字符以内
- SVG 元素紧凑精炼，去除重复冗余，同一视觉元素只出现一次

## 第四部分：steps 数组规范

- 数量：5-8 步（宁精勿多，保证每步都有对应的画布视觉变化）
- 每步 title/description/bubbleText 非空
- bubblePos.x/y 为数值（0-800 范围），默认优先使用左上角安全区（建议 24,24），并靠近当前讲解主体元素
- description 为规范解题过程（支持 $公式$）
- bubbleText 为简单讲解"为什么这样做"（支持 $公式$）
- 最后一步必须包含答案正确性验证
- 每一步都必须有对应的画布视觉变化，禁止"只有文字变、图不变"

## 第五部分：严禁事项

1. 禁止 TODO、占位符文本（"..."、"待补充"、"示例"）
2. 禁止 markdown 代码块标记
3. 禁止 JSON 以外的额外内容
4. 禁止 SVG 中出现未渲染的 LaTeX 原文
5. 禁止 <svg>、<script>、<html>、<body> 标签
6. 禁止页面级 UI 元素
7. 禁止全屏/缩放按钮
8. 禁止全部使用 sceneStep === N，必须有范围条件
9. 禁止全画布背景层
10. 禁止无语义装饰元素

## 第六部分：构图与逐步降噪规则

- 气泡禁区仅限左上局部，不得因此压缩或缩小教学主体。
- 主体视觉应占据主要可用区域，构图保持均衡，避免内容偏挤或留白失衡。
- 每一步只显示当前教学需要的公式和元素；前步不再使用的公式必须使用 `x-show` 隐去。
- 已复用的结论降级为辅助信息，不得与当前步骤的核心结论争夺视觉层级。
- 避免堆叠微小卡片，优先使用清晰、连续的主体视觉表达。
- `arrowTarget` 必须指向当前 `bubbleText` 实际解释的具体视觉点：优先填写对应公式、关键数字、图形标记或文字块的几何中心；禁止统一填写 `{x:400,y:300}`、整组场景中心或与当前步骤无关的位置。
- 生成每一步时，先确定当前讲解对象在 820×620 画布中的真实位置，再填写 `arrowTarget`；如果讲解对象是矩形里的文字，箭头必须指向文字块中心，不能指向矩形边缘或空白处。
- 所有带文字的 `rect`、标签和卡片必须按文字实际尺寸自适应：根据字号、字数和换行计算文本区域，再加四周至少 16px 内边距；禁止用固定小矩形容纳长度不确定的文字。
- 矩形内长文本必须主动换行或扩大矩形，并设置合理的 `font-size`、`line-height`、最大文本宽度和必要的 `overflow`/裁切规则；文字不得超出矩形、遮挡相邻元素或被裁掉。
- 文字和背景矩形必须使用相同的 `x-show` 条件，且每次文字内容变化时同步调整矩形宽高。完成后逐步检查每个场景，确保所有文字都在对应背景边界内。

## 第七部分：题意图案与预览图参考

- 如果附带题目预览图，先识别其中与题意直接相关的对象或几何关系，例如火车、桥、圆、道路、箱子、树、人物或题目明确提到的其他物体。
- 只有题目或预览图确实包含该对象，才在 `scene_svg` 中用简洁、可读的 SVG 线稿或微扁平图案复刻；不得凭空添加无关装饰。
- 题意图案只作辅助说明，放在画布边角或边缘的空闲区域，不得遮挡主体、公式或步骤标注，尺寸小于教学主体。
- 所有小元素（汽车、水果、人物、树、箱子、旗子、箭头起点、数字角标、角落图标、装饰性线稿、题意图标）应均匀分布在整幅画布可用区，充分利用中部/右侧/下方，元素间留白 ≥16px、互不压盖；画布整幅可用，无需为气泡预留左上禁区。
- 不得复制整张预览图、使用 `<image>` 贴图或让辅助图案抢夺核心数字和公式的视觉层级；没有题意对象时不要额外绘制图案。

## 第八部分：计算过程渐进隐去

- 计算题的中间算式、圈选、高亮、辅助线和临时结果必须归入步骤临时层，只使用 `x-show="sceneStep === N"`；切换到下一步或回看其他步骤时自动隐去。
- 只有后续步骤仍需引用的基础量或最终结论才可使用 `x-show="sceneStep >= N"` 保留；前步已经完成且后续不再使用的完整推导式必须删除显示。
- 承接前一步时只保留简短、低视觉层级的必要结论，用当前算式替换多条历史算式，禁止让公式随步骤层层叠加。
- 逐步检查每个 `sceneStep` 的画面：后续步骤中公式数量和辅助元素不得持续增长；画面拥挤时优先隐去已完成且不再引用的算式、轨迹和标注。

最后一行必须追加结束标记 <!--PARTS_END-->。
