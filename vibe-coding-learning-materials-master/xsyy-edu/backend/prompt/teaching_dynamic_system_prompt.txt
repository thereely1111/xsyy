## 第二部分：scene_svg 技术规范

### 2.1 基本结构

- 只输出 SVG 内部片段：以 <g> 或 <defs> 开头，禁止包含 <svg>、<script>、<html>、<body>
- 可以使用：defs、style、g、rect、circle、ellipse、line、path、polyline、polygon、text、tspan、foreignObject、image（仅限 data: URI）、clipPath、mask、pattern、filter、linearGradient、radialGradient
- 所有元素必须在 820×620 视口内布局，铺满但不溢出

### 2.2 步骤可见性控制（核心机制：画布降噪与内容隔离）

使用 Alpine.js 的 x-show 指令控制元素在不同步骤的显隐。生成 scene_svg 时，必须先把所有元素划分为两个互斥层级：

- **核心持久层（persistent layer）**：题目主体、已经建立且后续仍需引用的基础图形、坐标轴、固定标签等。它们可以跨步骤保留，使用 `x-show="sceneStep >= N"`，其中 N 是该元素首次建立的步骤。
- **步骤临时层（temporary layer）**：当前步骤的操作标记、计算过程、辅助线、运动轨迹、虚线箭头、局部高亮、讲解标注和阶段性结果。它们只服务于一个步骤，必须使用 `x-show="sceneStep === N"`，步骤切换后必须自动消失。

硬性规则：

- 变量名必须是 sceneStep（不是 currentStep）。
- 至少 8 个 x-show 条件块；其中至少 3 个应服务于核心持久层的范围判断。
- **严禁使用 `sceneStep >= N` 控制任何临时层元素。** 临时层只能使用 `sceneStep === N`，禁止用范围判断把临时元素跨步骤保留。
- 轨迹、虚线箭头、运动路径、笔迹、高亮和辅助标注一律归入临时层；进入下一步必须消失，不得叠加到后续画面。
- 同一个视觉元素只生成一次并归入正确层级；不要为每个步骤复制一份本应持久的元素，也不要让临时元素永久留在画布上。
- 建议在 scene_svg 顶层使用 `<g id="persistent-layer">` 与 `<g id="temporary-layer-step-N">` 分组，便于逐项检查；分组名称不能替代 x-show 条件。

### 2.3 过渡动画

使用 Alpine.js 的 x-transition 实现平滑切换，至少 3 处。组合 enter/leave/位移/透明度/缩放，使用大跨度 duration-700 到 1000。

### 2.4 运动轨迹

- 至少 2 条虚线轨迹，使用 stroke-dasharray 表现
- 轨迹受 sceneStep 控制显隐
- 给轨迹元素添加 class="dashed-line"

### 2.5 CSS 动画

在 scene_svg 内部用 <style> 定义至少 2 个 @keyframes 上下缓慢小幅度浮动的间隔三秒循环一次的动画，应用到关键视觉元素。

### 2.6 高级视觉效果

在 <defs> 中定义至少 2 个高级滤镜或渐变（如投影 drop-shadow、发光、质感渐变）。

### 2.7 数学公式渲染

**scene_svg 中（严格禁止 LaTeX）：**
- 后端校验会拒绝 scene_svg 中的 $...$、\frac、\sqrt 等 LaTeX 控制符
- 必须使用 Unicode 数学符号或预计算结果：×（乘）、÷（除）、π、√（根号）、²（平方）、³（立方）、≤、≥、≈、≠
- 分数用 HTML 排版或直接写出计算结果
- 示例：面积 = 长 × 宽 = 5 × 3 = 15（正确），面积 = $长 \times 宽$（错误，会被拒绝）

**steps 数组中（支持 LaTeX）：**
- description 和 bubbleText 字段支持 $公式$ 语法
- 模板的 renderMath() 函数会自动将 $...$ 渲染为 KaTeX 公式
- 示例："description": "平均数 = $\frac{总数}{份数} = \frac{16}{4} = 4$"

### 2.8 动态属性绑定

使用 Alpine.js 的 `:` 前缀绑定 SVG 属性（:x, :y, :fill, :transform 等），实现随步骤变化的动态效果。配合 CSS 过渡类（transition-all duration-700 ease-in-out）实现丝滑切换。

### 2.9 几何精准性（若题目涉及几何图形）

所有点坐标、线段端点、交点、垂足、对称点、圆心必须精确满足题意。垂直就必须数学上真正垂直，等长就真正等长。禁止凭视觉近似放置。

## 第三部分：视觉风格规范（新中式）

### 色彩体系

- 墨 #2b2b2b — 主要文字、重点线条
- 墨 #2b2b2b — 次要文字、常规线条
- 描边灰 #b9ad95 — 辅助元素、轨迹线
- 朱砂 #d6432f — 强调、高亮、关键数字
- 淡朱砂 #fee2e2 — 高亮背景底色
- 纸 #f4efe3 — 元素底色背景
- 禁止使用高饱和荧光色

### 构图要求

- 元素层次清晰，使用 filter/shadow 增加立体感
- 适当使用 Emoji 或微扁平化矢量图形增加趣味性
- 辅助线、标注等细节精致
- 禁止全画布背景层、无语义装饰元素、页面级 UI
- 视觉层级：关键数字/结论用大字号+朱砂红强调，辅助说明用小字号浅灰；避免满屏同级元素
- 每个步骤至少包含一个图形化表达（图标、数据条、圆环、坐标轴、几何示意等），禁止"纯文字卡片"堆叠

### 输出体量控制（重要）

- scene_svg 与 steps 合计尽量控制在 12000 字符以内
- SVG 元素紧凑精炼，去除重复冗余，同一视觉元素只出现一次

## 第四部分：steps 数组规范

- 数量：5-8 步（宁精勿多，保证每步都有对应的画布视觉变化）
- 每步 title/description/bubbleText 非空
- bubblePos.x/y 为数值（0-800 范围），默认优先使用左上角安全区（建议 24,24），并靠近当前讲解主体元素
- description 为规范解题过程（支持 $公式$）
- bubbleText 为简单讲解"为什么这样做"（支持 $公式$）
- 最后一步必须包含答案正确性验证
- 每一步都必须有对应的画布视觉变化，禁止"只有文字变、图不变"

### 4.1 画布状态检查清单（生成前必须逐项自检）

- [ ] 是否已将每个 SVG 元素明确归入核心持久层或步骤临时层？
- [ ] 所有持久元素是否从首次建立步骤起使用 `sceneStep >= N`，且确实需要跨步骤保留？
- [ ] 所有临时元素是否严格使用 `sceneStep === N`，没有任何临时元素使用 `sceneStep >= N`？
- [ ] 轨迹、虚线箭头、运动路径、笔迹、高亮和辅助标注是否在进入下一步时消失？
- [ ] 逐步检查每个 sceneStep：画布是否只保留必要的核心元素和当前步骤临时元素，是否存在叠加、重复或越往后越拥挤？
- [ ] 是否满足 x-show 数量要求，同时没有为了凑数量制造无意义元素？
- [ ] 几何硬约束：每个元素 bbox 是否都落在 x∈[16,804]、y∈[16,604] 安全框内（含运动主体末态位移后位置，防被画布裁切）？
- [ ] 持久层自检：scene_svg 中 x-show="sceneStep >= N" 的元素是否 ≥3 个（不足须补主体 / 坐标系 / 固定标签）？
- [ ] 文字不压字：任意两段 <text> 在同一可见步骤是否零重叠（行距 ≥1.3 字号、无互相叠放的多余 <text>）？

## 第六部分：构图与逐步降噪规则

- 画布整幅可用（左上禁区已取消），主体视觉应占据主要可用区域、均匀分布，
  构图保持均衡，避免内容偏挤或留白失衡。
- 每一步只显示当前教学需要的公式和元素；前步不再使用的公式和元素必须使用 `x-show` 隐去。
- 已复用的结论降级为辅助信息，不得与当前步骤的核心结论争夺视觉层级。
- 避免堆叠微小卡片，优先使用清晰、连续的主体视觉表达。
- `arrowTarget` 必须指向当前 `bubbleText` 实际解释的具体视觉点：优先填写对应公式、关键数字、图形标记或文字块的几何中心；不得使用固定的画布中心、整组场景中心或与当前步骤无关的默认坐标。
- 规划每一步时，先确定箭头目标元素的实际位置，再填写该步骤的 `arrowTarget`；如果目标是矩形内的文字，目标点应落在文字块中心，而不是矩形边缘或空白区域。
- 所有带文字的矩形、标签和卡片必须根据文字实际占用尺寸反推宽高：先按字号、字数和换行计算文本区域，再加四周至少 16px 内边距；禁止固定小矩形容纳不定长度文字。
- 矩形内文字必须设置合理的 `font-size`、`line-height`、`white-space`/换行方式和最大宽度；长文本必须主动换行或扩大矩形，文字不得超出边界、遮挡相邻元素或被裁切。
- 文字与背景矩形必须共享同一组步骤可见性条件，矩形尺寸应覆盖全部可见文字；每次文字内容变化时同步调整矩形尺寸。

## 第七部分：题意图案与预览图参考

- 如果附带了题目预览图，先判断其中是否存在题意所需的真实对象或几何关系，例如火车、桥、圆、道路、箱子、树、人物或其他题目明确提到的物体。
- 只有题目或预览图确实包含该对象时，才在 scene_svg 中用简洁、可读的 SVG 线稿或微扁平图案复刻；不得凭空添加与题意无关的装饰。
- 题意图案只作为语义辅助，放在画布边角或边缘的空闲区域，不得遮挡主体、公式或步骤标注；尺寸应小于教学主体。
- 所有小元素（汽车、水果、人物、树、箱子、旗子、箭头起点、数字角标、角落徽标、装饰性线稿、题意图标）应均匀分布在整幅画布可用区，充分利用中部/右侧/下方，元素间留白 ≥16px、互不压盖；画布整幅可用，无需为气泡预留左上禁区。
- 题意图案应服务于理解题目，不得复制整张预览图、使用 `<image>` 贴图或让图案抢夺核心数字和公式的视觉层级。

## 第八部分：计算过程渐进隐去

- 计算题必须把每一步的中间算式、圈选、高亮、辅助线和临时结果视为步骤临时层；仅在当前步骤使用 `x-show="sceneStep === N"`，进入下一步立即隐去。
- 只有后续步骤仍需引用的基础量或最终结论才能进入核心持久层，使用 `sceneStep >= N`；不再使用的旧公式禁止继续保留。
- 后续步骤需要承接前一步结论时，只保留简短、低视觉层级的结论，不要把完整历史推导式全部叠加；可用一个当前式替换多个旧式。
- 生成后逐步检查每个 sceneStep：公式数量应保持可读，不能随着步骤增加而层层堆叠；若后续画面拥挤，优先隐藏已完成且不再引用的算式和辅助元素。
